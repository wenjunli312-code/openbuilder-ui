OpenBuilder

面向 CMake 项目的声明式工作区与构建工具，
一份 manifest.yaml 描述所有依赖，支持 ARM64 / ARMv7 交叉编译，
编译产物自动上传 S3，可随时回溯下载。

Why OpenBuilder

为什么需要 OpenBuilder

嵌入式项目中，多个 Git 仓库（sensor、perception、control…）有依赖关系，手动 cmake 调用容易出错，交叉编译更是繁琐。OpenBuilder 用一份 manifest 把这些问题自动化。

📋 声明式依赖管理

所有仓库写在 manifest.yaml 里，OpenBuilder 自动解析 deps、计算拓扑顺序、克隆源码。你只需要声明"要什么"，不用管"怎么编译"。

🔄 自动交叉编译

设一次 openbuilder configure platform linux-arm64，之后的每次 build 自动通过 Docker 调起 dockcross 交叉编译镜像，CMakeLists.txt 无需任何修改。

☁️ 产物 S3 持久化

每次 openbuilder publish 把 target/ 打包成 tar.gz，按 build ID 上传 S3，任何时候都能用 openbuilder download --id N 回溯历史产物。

🗂️ 虚拟项目节点

manifest 支持没有 url 的"虚拟节点"，用来给真实仓库分组。openbuilder build perception --recursive 自动展开虚拟节点的依赖链，一次构建完整系统。

Workspace

工作区目录结构

运行 openbuilder init 后，在当前目录创建标准工作区布局，灵感来自 Zephyr 的 west。

my-project/
.openbuilder/ ← 工作区配置目录（始终存在）
config.yaml ← 工作区 + CMake 全局设置
manifest.yaml ← 项目 manifest（repos、deps）
src/ ← 所有源码仓库（git clone 到这里）
sensor-abstraction/
vehicle-bridge/
perception-core/
build/ ← CMake out-of-tree 构建产物
target/ ← install_prefix，最终编译产物
linux-arm64/ ← 交叉编译按平台隔离
release/ ← 编译类型隔离（debug / release / releasewithdebuginfo）
lib/ ← .so / .a 文件
bin/ ← 可执行文件

manifest.yaml 示例

.openbuilder/manifest.yaml
# OpenBuilder manifest workspace: name: perception-workspace config_repo: git@github.com:org/config.git current_project: perception-core projects: - name: sensor-abstraction url: git@github.com:wenjunli312-code/sensor-abstraction.git revision: main deps: [] - name: vehicle-bridge url: git@github.com:wenjunli312-code/vehicle-bridge.git revision: develop deps: - sensor-abstraction - name: perception-core # 虚拟节点（无 url） deps: - sensor-abstraction - vehicle-bridge s3: endpoint: http://localhost:9000 bucket: openbuilder-builds region: us-east-1 access_key_id: minioadmin secret_access_key: minioadmin cmake: build_type: release

依赖拓扑解析

给定目标 perception-core --recursive，OpenBuilder 自动：

1. 识别 perception-core 是虚拟节点
2. 展开 deps → vehicle-bridge, sensor-abstraction
3. vehicle-bridge 依赖 sensor-abstraction
4. 拓扑排序：sensor-abstraction → vehicle-bridge → perception-core
5. 按顺序执行 cmake configure + build + install
✅ 循环依赖检测 — 检测到 circular deps 时立即报错并退出
Commands

命令一览

所有命令通过 Click 实现，提供完整的 --help 和 Tab 自动补全（shell-completion）。

打印当前版本
openbuilder version # → OpenBuilder 0.2.0
在当前目录初始化工作区
openbuilder init # → Initialized OpenBuilder workspace at /path/to/my-project # → Config repo: git@github.com:org/config.git # → Run 'openbuilder configure project ' to set the project # → Or: eval "$(openbuilder init --export)"

init 做了什么

① 创建 src/、build/、target/ 目录；② 从配置仓库克隆 .openbuilder/ 到工作区；③ 合并 s3.yaml（S3 配置）；④ 写入 manifest.yaml。

克隆一个或多个 repo 到 src/
openbuilder clone sensor-abstraction vehicle-bridge # → Cloning 'sensor-abstraction' from git@github.com:org/sensor-abstraction (branch: main) → src/sensor-abstraction # → Cloning 'vehicle-bridge' from git@github.com:org/vehicle-bridge (branch: develop) → src/vehicle-bridge # → Done.

clone 特性

· 自动按拓扑顺序克隆（有 deps 的 repo 后克隆）
· 跳过已存在的目录（不会重复 clone）
· REPOS 参数必填，支持一次传多个

构建（CMake configure + build + install）
openbuilder build # 构建所有 repos openbuilder build sensor-abstraction # 只构建指定 repo openbuilder build perception-core -r # 递归构建（含 deps） openbuilder build -j 8 --build-type release # 指定并行数 + build type # 输出示例： ==> Building 'sensor-abstraction' $ cmake -B build/sensor-abstraction -S src/sensor-abstraction ... $ cmake --build build/sensor-abstraction $ cmake --install build/sensor-abstraction ==> Building 'vehicle-bridge' $ cmake ... -DCMAKE_PREFIX_PATH=target/lib/cmake ... Build complete.

build 的关键逻辑

· 拓扑排序：按 deps 依赖顺序构建，保证依赖库先就位
· CMAKE_PREFIX_PATH：自动把已安装的库路径注入 CMake，跨 repo 依赖无需手动 pkg-config
· --recursive：虚拟节点的 deps 自动展开成完整构建列表
· Build complete. 判断：必须看到 "Build complete." 才算成功（不能只看 returncode）

配置当前项目和交叉编译平台
openbuilder configure project perception-core # 设置当前项目 openbuilder configure platform linux-arm64 # 设置目标平台（ARM64）

configure platform 的效果

写入 manifest.yaml 的 workspace.current_platform，之后的 build 自动切换到 Docker 交叉编译模式，不再调用宿主机 gcc/g++。

打包并发布 target/ 到 S3
openbuilder publish list # 查看已发布的 builds openbuilder publish upload --s3 # 上传到 S3（自动分配 build ID） openbuilder publish rm 10042 # 删除本地 build 记录 # upload 输出： target hash: sha256:abc123... (对 target/ 内容做 SHA256) build id: 10042 (从 S3 原子分配，避免并发冲突) uploading tarball to S3: build/10042/target-10042.tar.gz uploading info to S3: build/10042/build-info-10042.json Published to S3 as build 10042.
从 S3 下载历史 build 产物
openbuilder download --id 10042 # 下载指定 build 的 tar.gz 并解压到 target/ openbuilder download --platform linux-arm64 # 下载平台 Docker 镜像（.tar.gz from S3）
查看平台镜像状态
openbuilder platform list # → Platform Image Status # → linux-arm64 dockcross/linux-arm64-full loaded # → linux-armv7 dockcross/linux-armv7 not-loaded # → linux-x86_64 (native) —
显示当前工作区信息
openbuilder show # → Workspace: /path/to/my-project # → Platform: linux-arm64 # → Config repo: git@github.com:org/config # → Projects: 3 repos
查看所有 repo 的 git 状态
openbuilder status # → repo branch commit dirty # → sensor-abstraction main 7450c85 no # → vehicle-bridge develop ac2c3f5 yes ← 有未提交修改
清理构建产物
openbuilder clean # 删除 build/ 目录（CMake 缓存） openbuilder clean --target # 删除 target/（清理 install 产物） openbuilder clean --all # 删除 build/ + target/
检查环境问题
openbuilder doctor # → Checking environment... # → ✅ Python 3.11 # → ✅ Git found # → ✅ Docker available # → ✅ S3 configured # → ✅ CMake found # → ✅ OpenBuilder workspace found # → 0 issue(s) found.
Cross-Compilation

跨平台交叉编译

OpenBuilder 通过 Docker + dockcross 镜像实现零配置交叉编译。CMakeLists.txt 完全不需要改动，toolchain 在 cmake configure 时自动注入。

🦄

linux-arm64

ARM 64-bit (AArch64)
dockcross/linux-arm64-full
5.42 GB 镜像

🦄

linux-armv7

ARM 32-bit (hardfloat)
dockcross/linux-armv7
4.61 GB 镜像

💻

linux-x86_64

x86 本地开发/测试
直接调用系统 gcc/cmake
无需 Docker

1. download --platform

从 S3 下载镜像 .tar.gz
→ docker load 到本地

→

2. configure platform

写入 manifest.yaml
current_platform=linux-arm64

→

3. build

自动调起 docker run --rm
dockcross/linux-arm64-full
注入 dockcross.cmake

→

4. 产物写入 target/

target/linux-arm64/release/
lib/ + bin/ + include/

build 在 Docker 模式下的 cmake 实际调用
docker run --rm \ -v /path/to/workspace:/src \ -v /path/to/workspace/target/linux-arm64/release:/target \ -w /src \ dockcross/linux-arm64-full \ bash -c "cmake -B build/sensor-abstraction -S src/sensor-abstraction -DCMAKE_INSTALL_PREFIX=/target -DCMAKE_BUILD_TYPE=release && cmake --build build/sensor-abstraction && cmake --install build/sensor-abstraction"

Quick Start

快速上手

安装（可编辑模式）
pip install -e . openbuilder version # → OpenBuilder 0.2.0
初始化工作区 + 配置项目 + 克隆源码
mkdir my-project && cd my-project openbuilder init openbuilder configure project perception-core openbuilder clone sensor-abstraction vehicle-bridge
设置平台 + 构建
openbuilder download --platform linux-arm64 # 下载 dockcross 镜像（首次） openbuilder configure platform linux-arm64 # 设置 ARM64 编译 openbuilder build -j 8 --build-type release # 交叉编译！
发布产物到 S3，随时可回溯
openbuilder publish upload --s3 # → Published to S3 as build 10042. # 任意时候回溯： openbuilder download --id 10042 # → Downloaded and extracted build 10042 to target/
